## O fluxo de proteção

O fluxo canônico separa encontrar informação pessoal de produzir uma resposta:

```text
conteúdo do usuário
  ─▶ adaptador de Detecção (Rampart Q4 ou modelo do chamador)
  ─▶ anonymizer e placeholders
  ─▶ uma sessão de privacidade para uma conversa privada
  ─▶ conteúdo protegido para um adaptador/modelo de Geração
  ◀─ resposta reidratada; mapping privado fica no dispositivo
```

Detectores determinísticos cobrem email, telefone, cartão, IBAN, SSN, IP e URL.
Dicionário e vault da sessão mantêm correspondências estáveis. Rampart Q4 é um
modelo de Detecção para nomes, endereços e IDs; Gemini Nano, Gemma e modelos de
provedor são modelos de Geração. `ner:` continua como alias de compatibilidade
para `detection:`.

## Vault, mapping e sessão de privacidade

- **Vault** atribui um placeholder estável a cada valor distinto.
- **Mapping privado** relaciona placeholders ao conteúdo original. É o segredo:
  mantenha-o em memória e nunca o serialize para fora do dispositivo.
- **Sessão de privacidade** mantém um vault entre turnos e pertence a uma
  conversa privada. Uma nova conversa recebe uma nova sessão.

```ts
const conversation = privacy.createSession()
await conversation.anonymize("First, about João…")
await conversation.anonymize("Tell João I said hi") // mesmo placeholder
conversation.rehydrate(assistantReply)
```

Sessões explícitas são recomendadas em várias mensagens. Sessões fornecidas são
emprestadas; adaptadores nunca as limpam. OpenAI e AI SDK podem possuir uma
sessão implícita de uma chamada; TanStack exige sessão fornecida pelo chamador.

## Fronteiras de confiança e ciclo de vida

No dispositivo, o app possui o adaptador de Detecção, a sessão e a chamada de
Geração; conteúdo protegido pode ir para um provedor enquanto o mapping fica
local. Em uma rota ou gateway, adaptador e mapping pertencem ao seu servidor e
protegem contra o provedor. Crie uma sessão por requisição, nunca uma sessão de
módulo compartilhada entre usuários.

Adapters inline resolvem `session`, depois `anonymizer`, depois o padrão. A
limpeza ocorre mesmo quando modelo ou abort falha, preservando a falha primária.
TanStack passa hydration e só entra em runs da mesma sessão viva; persistência,
reload completo, restauração entre abas e nova sessão não restauram conversa.
