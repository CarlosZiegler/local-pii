## Der Schutzablauf

Der kanonische Ablauf trennt das Erkennen persönlicher Informationen vom
Erzeugen der Antwort:

```text
Benutzerinhalt
  ─▶ Erkennungs-Adapter (Rampart Q4 oder Aufrufermodell)
  ─▶ Anonymizer und Platzhalter
  ─▶ eine Privacy-Session für eine private Konversation
  ─▶ geschützter Inhalt an Generierungs-Adapter/-modell
  ◀─ rehydrierte Antwort; privates Mapping bleibt auf dem Gerät
```

Deterministische Detektoren erkennen E-Mail, Telefon, Karte, IBAN, SSN, IP und
URL. Dictionary und Session-Vault sorgen für stabile Treffer. Rampart Q4 ist
ein Erkennungsmodell für Namen, Adressen und IDs; Gemini Nano, Gemma und
Provider-Modelle sind Generierungsmodelle. `ner:` bleibt der
Kompatibilitätsalias für `detection:`.

## Vault, Mapping und Privacy-Session

- **Vault** weist jedem unterschiedlichen Wert einen stabilen Platzhalter zu.
- **Privates Mapping** verbindet Platzhalter mit ursprünglichem Inhalt. Es ist
  das Geheimnis: im Speicher halten und nie vom Gerät serialisieren.
- **Privacy-Session** hält einen Vault über mehrere Turns und gehört zu einer
  privaten Konversation. Eine neue Konversation erhält eine neue Session.

```ts
const conversation = privacy.createSession()
await conversation.anonymize("First, about João…")
await conversation.anonymize("Tell João I said hi") // derselbe Platzhalter
conversation.rehydrate(assistantReply)
```

Explizite Sessions werden für mehrere Turns empfohlen. Übergebene Sessions sind
geliehen und werden von Adaptern nie geleert. OpenAI und AI SDK können eine
implizite Session für einen Aufruf besitzen; TanStack verlangt eine Session des
Aufrufers.

## Vertrauensgrenzen und Lifecycle

Auf dem Gerät besitzt die App Erkennungs-Adapter, Session und Generierungsaufruf;
geschützter Inhalt kann an einen Provider gehen, während das Mapping lokal
bleibt. In Route oder Gateway gehören Adapter und Mapping deinem Server und
schützen gegenüber dem Provider. Eine Session pro Request erzeugen, nie eine
gemeinsame Modul-Session.

Inline-Adapter lösen `session`, dann `anonymizer`, dann den Standard auf. Cleanup
läuft auch bei Modell- oder Abort-Fehlern; der primäre Fehler bleibt erhalten.
TanStack reicht Hydration durch und joint nur Runs derselben lebenden Session;
Persistence, vollständiger Reload, Cross-Tab-Wiederherstellung und eine neue
Session stellen eine private Konversation nicht wieder her.
