## Das private Mapping ist das Geheimnis

Die Verbindung von Platzhalter zu ursprünglichem Inhalt kann geschützten Inhalt
allein wiederherstellen. Halte sie im Speicher. Nicht loggen, an Analytics oder
Crash-Reporter senden oder außerhalb eines Plattform-Keystores persistieren.
Originalinhalt darf nicht in Telemetrie gelangen, die vor der Erkennung läuft.

## Was ein Generierungs-Provider sieht

| Strategie            | Wert              | Gleichheit            | Typ               |
| -------------------- | ----------------- | --------------------- | ----------------- |
| `sequential()`       | nicht offengelegt | innerhalb der Session | ja (`[EMAIL_1]`)  |
| `hashed({ secret })` | nicht offengelegt | stabil mit Schlüssel  | ja                |
| `token()`            | nicht offengelegt | nicht offengelegt     | nicht offengelegt |
| `token({ secret })`  | nicht offengelegt | stabil mit Schlüssel  | nicht offengelegt |

Gleichheit kann für stabile Referenzen nützlich sein, ist aber Metadaten. Für
Tools und maschinell verarbeitete Ausgabe ist `token()` die sicherere Wahl.

## Warum ungekeytes Hashing verboten ist

Ein einfacher Hash von E-Mail oder Telefon ist erratbar: Ein Provider kann
Kandidaten offline neu berechnen. `hashed` und `token({ secret })` verwenden
einen zufälligen gerätelokalen Schlüssel; ohne ihn ist ein Treffer nicht
verifizierbar.

Tool-Argumente sind eine Offenlegungsgrenze. Rehydrierung gibt deinem Tool den
Originalwert; eine Weiterleitung ist eine neue Offenlegung unter Verantwortung
der Anwendung. Siehe [Tool Calls](/de/docs/tool-calls).
