## Das Mapping ist das Geheimnis

`mapping` (`Platzhalter → Original`) ist das Einzige, das die Anonymisierung
rückgängig machen kann. Halte es **im Speicher**. Logge es nicht, sende es
nicht an Analytics- oder Crash-Reporter-Dienste und persistiere es nicht,
außer du musst — und wenn du musst, verwende den Plattform-Keystore
(`expo-secure-store`), niemals einfachen Speicher.

Halte außerdem den **Rohtext** aus Logs/Analytics/Crash-Reportern heraus, die
*vor* der Anonymisierung laufen.

## Was jede Strategie gegenüber dem Provider preisgibt

| Strategie | Gibt den Wert preis? | Gibt Gleichheit preis? | Gibt den Typ preis? |
| --- | :---: | :---: | :---: |
| `sequential()` | nein | innerhalb einer Session | ja (`[EMAIL_1]`) |
| `hashed({ secret })` | nein | ja (stabil) | ja |
| `token()` (zufällig) | nein | nein | nein |
| `token({ secret })` | nein | ja (stabil) | nein |

„Gibt Gleichheit preis" bedeutet: Der Provider kann erkennen, dass zwei
Erwähnungen dieselbe Entität sind. Das ist ein Feature für stabile IDs, aber
mehr Metadaten als `sequential` innerhalb einer Session — weshalb
`sequential` der Standard bleibt.

## Warum ungekeytes Hashing verboten ist

Ein einfacher Hash eines Werts (`sha256(email)`) als Platzhalter ist ein
**Privacy-Leak, schlimmer als sequenzielle Nummerierung**:

- Platzhalter werden an den Provider gesendet.
- PII hat niedrige Entropie — Namen, Telefonnummern und E-Mails sind
  erratbar/enumerierbar.
- Wer also den Platzhalter besitzt, kann einen erratenen Wert **offline**
  bestätigen, indem er den Hash neu berechnet (ein Rainbow-/
  Dictionary-Angriff).

local-pii bietet daher ausschließlich **gekeytes** Hashing (`hashed` /
`token({ secret })`) mit einem zufälligen ≥128-Bit-Secret, das on device
erzeugt wird (`getOrCreateDeviceSecret`) und es nie verlässt. Ohne den Key
ist eine korrekte Vermutung nicht verifizierbar.

## Tool Calls sind ein Disclosure-Ziel

Das Rehydrieren von Tool-Call-Argumenten gibt deinem Tool die echten Werte —
angemessen für deinen eigenen Code, aber eine erneute Offenlegung, wenn das
Tool Daten an Dritte weiterleitet. Siehe [Tool Calls](/de/docs/tool-calls).
