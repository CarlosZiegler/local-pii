Das Q4-[Rampart](https://huggingface.co/nationaldesignstudio/rampart)-Modell
ist ein **Erkennungsmodell** für Namen, Adressen und IDs. Es läuft lokal über
`onnxruntime-react-native`; das separate Generierungsmodell erhält nur
geschützten Inhalt.

```bash
bun add onnxruntime-react-native expo-asset expo-file-system @local-pii/model-rampart
```

Erforderlich ist ein Dev Client / Prebuild, nicht Expo Go.

## Metro

```js
const { getDefaultConfig } = require("expo/metro-config")
const { withLocalPiiMetro } = require("@local-pii/core/metro")

module.exports = withLocalPiiMetro(getDefaultConfig(__dirname))
```

## Erkennung konfigurieren

```ts
import { createAnonymizer } from "@local-pii/core"
import { rampart } from "@local-pii/core/expo"

const privacy = createAnonymizer({
  detection: rampart({
    model: require("@local-pii/model-rampart/assets/rampart-q4.onnx"),
  }),
})
```

Das Laden erfolgt faul: Die erste Anonymisierung löst das paketierte Asset auf
und startet die Rampart-Runtime. Anwendungen mit dem veröffentlichten
Modellpaket führen das `fetch-model`-Entwicklungsskript des Monorepos nicht aus.

Wenn das Modell nicht lädt oder die Inferenz fehlschlägt, schlägt die
konfigurierte Erkennung standardmäßig geschlossen fehl. Verwende
`strict: false` nur, wenn der Rückfall auf deterministische Erkennung eine
bewusste Produktrichtlinie ist. `ner:` bleibt ein Kompatibilitätsalias. `CITY`,
`STATE` und `ZIP_CODE` bleiben standardmäßig im Text; `keep` oder `redact`
ändern diese Richtlinie.
