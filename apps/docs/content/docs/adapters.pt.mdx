Os adaptadores implementam o mesmo fluxo: Detecção → anonymizer → sessão de
privacidade → adaptador de Geração ou callback inline → resultado reidratado.
Eles protegem conteúdo semântico e preservam campos de controle do protocolo.

## Chamadas inline — `@local-pii/core/inline`

Use inline para qualquer modelo de Geração no mesmo processo. Ele encaminha o
mesmo `AbortSignal` e reidrata com um ciclo de vida seguro em `finally`:

```ts
import { runInlineText } from "@local-pii/core/inline"

const answer = await runInlineText({
  session: conversation,
  input: "Email ana@acme.com",
  signal,
  call: (protectedContent, { signal }) =>
    generationModel.generate(protectedContent, { signal }),
})
```

`runInlineJson` protege folhas string sem mutar a entrada. A prioridade é
`session`, depois `anonymizer`, depois o anonymizer padrão. Sessão criada pelo
adaptador é limpa; sessão fornecida é emprestada e nunca é limpa pelo
adaptador. Falha de limpeza não substitui a falha primária do modelo ou abort.

Callbacks inline genéricos e modelos de Detecção fornecidos pelo chamador
executam como código confiável do chamador. `@local-pii/core` protege a fronteira de
Geração deles; não os executa em sandbox.

## OpenAI / Grok — `@local-pii/core/openai`

```ts
import OpenAI from "openai"
import { withPiiOpenAI } from "@local-pii/core/openai"

const client = withPiiOpenAI(new OpenAI({ apiKey }))
const result = await client.chat.completions.create({
  model: "gpt-4o-mini",
  messages,
  tools,
})
```

| Contrato                         | Comportamento testado                                                                                                                                      |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Valores semânticos protegidos    | Texto de mensagens e sistema, argumentos de tools e resultados de tools são protegidos antes do cliente.                                                   |
| Valores semânticos reidratados   | Texto, deltas de streaming, argumentos entregues à tool e resultados são reidratados em seus limites de protocolo.                                         |
| Controle / opacos preservados    | Papéis, IDs, modelo/opções, nomes de tools, metadados e campos opacos do provedor são preservados; campos pessoais continuam responsabilidade do chamador. |
| Variantes não suportadas / erros | Formatos de cliente não suportados falham sem fallback silencioso. Abort e erros do provedor preservam a falha primária; use `token()` em JSON/tools.      |

O wrapper estrutural também cobre Grok/xAI, Groq, Together, OpenRouter e
Ollama. Uma sessão implícita é criada com o wrapper e reutilizada entre suas
chamadas. Use um wrapper por conversa privada ou passe `{ session }` para
deixar o ownership explícito. Loops manuais podem usar `createPiiChat`,
`rehydrateToolArgs` e `createStreamingRehydrator`.

## Vercel AI SDK — `@local-pii/core/ai-sdk`

```ts
import { openai } from "@ai-sdk/openai"
import { streamText } from "ai"
import { withPii } from "@local-pii/core/ai-sdk"

const model = withPii(openai("gpt-5.2"), { session: conversation })
const result = streamText({ model, prompt })
```

| Contrato                         | Comportamento testado                                                                                                                                                    |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Valores semânticos protegidos    | Texto de sistema/usuário/assistente, inputs/outputs de tools e JSON estruturado são protegidos. Reasoning é opaco e permanece responsabilidade do chamador.              |
| Valores semânticos reidratados   | Texto, argumentos antes da tool e resultados no passo seguinte são reidratados. Partes de reasoning passam sem alteração.                                                |
| Controle / opacos preservados    | Tipos, IDs, papéis, reasoning, nomes, aprovações, opções e marcadores de stream permanecem iguais; metadados do chamador não são inspecionados.                          |
| Variantes não suportadas / erros | Conteúdo sem suporte e streams inválidos falham. Aborts e erros do provedor preservam a falha exata; um abort observado antes da fronteira impede a chamada ao provedor. |

`withPii` é middleware e não exige wrapper de tool. Sessão fornecida é
emprestada; sem ela, o middleware possui uma sessão vinculada à instância e a
reutiliza entre chamadas. Crie um novo wrapper para uma nova conversa privada.
O playground fixa `ai@7.0.57`, `@ai-sdk/react@4.0.61` e
`@browser-ai/core@3.0.0`.

## TanStack AI — `@local-pii/core/tanstack`

```ts
import { createAnonymizer, token } from "@local-pii/core"
import { piiConnection } from "@local-pii/core/tanstack"

const session = createAnonymizer({ placeholders: token() }).createSession()
const connection = piiConnection(browserConnection, { session })
// useChat({ connection })
```

| Contrato                         | Comportamento testado                                                                                                                             |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Valores semânticos protegidos    | Mensagens de texto, conteúdo estruturado suportado, inputs/outputs de tools e limites de stream são protegidos sem mutação.                       |
| Valores semânticos reidratados   | Deltas, valores estruturados, argumentos e resultados de tools são reidratados no limite TanStack.                                                |
| Controle / opacos preservados    | Papéis, IDs, tipos de evento, marcadores de fim/erro e `data` opaco são preservados; hydration passa diretamente.                                 |
| Variantes não suportadas / erros | `UnsupportedTanStackSemanticContentError` rejeita partes semânticas não suportadas; abort, limpeza e runs sobrepostos preservam a falha primária. |

O contrato é pinado em `@tanstack/ai@0.43.1`, `@tanstack/ai-client@0.23.1` e
`@tanstack/ai-react@0.19.1`. O chamador fornece uma sessão por conversa.
Hydration e `joinRun` funcionam apenas na mesma sessão viva. Persistência,
restauração após reload completo, entre abas e com nova sessão não são
suportadas. Desde 0.1.0, migre partes semânticas não suportadas para texto ou
estrutura suportada em vez de depender de adivinhação.

## Escolha uma estratégia de placeholder

Use `sequential()` legível para texto comum, `hashed({ secret })` com chave
quando igualdade estável for necessária e `token()` opaco para tools ou JSON
processado por máquina. O mapping privado nunca é um campo do protocolo e deve
permanecer dentro da fronteira de confiança do chamador.
