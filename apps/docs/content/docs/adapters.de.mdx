title: Adapter
description: Geschützte und rehydrierte Werte bei Inline-, OpenAI-, AI-SDK- und TanStack-Adaptern.
---

Alle Adapter folgen demselben Ablauf: Erkennung → Anonymizer → Privacy-Session
→ Generierungs-Adapter oder Inline-Callback → rehydriertes Ergebnis. Semantische
Inhalte werden geschützt, Protokoll-Steuerfelder bleiben erhalten.

## Inline-Aufrufe — `local-pii/inline`

Inline eignet sich für jedes Generierungsmodell im selben Prozess. Der Adapter
reicht dasselbe `AbortSignal` weiter und rehydriert in einem
`finally`-sicheren Lifecycle:

```ts
import { runInlineText } from "local-pii/inline"

const answer = await runInlineText({
  session: conversation,
  input: "E-Mail ana@acme.com",
  signal,
  call: (protectedContent, { signal }) =>
    generationModel.generate(protectedContent, { signal }),
})
```

`runInlineJson` schützt String-Blätter tief und ohne Mutation. Die Priorität
ist `session`, dann `anonymizer`, dann der Standard-Anonymizer. Eine vom Adapter
erzeugte Session wird bereinigt; eine übergebene Session ist geliehen und wird
nie vom Adapter geleert. Ein Cleanup-Fehler ersetzt den primären Modell- oder
Abort-Fehler nicht.

Generische Inline-Callbacks und vom Aufrufer bereitgestellte Erkennungsmodelle
werden als vertrauenswürdiger Aufrufercode ausgeführt. `local-pii` schützt ihre
Generierungsgrenze; es führt sie nicht in einer Sandbox aus.

## OpenAI / Grok — `local-pii/openai`

```ts
import OpenAI from "openai"
import { withPiiOpenAI } from "local-pii/openai"

const client = withPiiOpenAI(new OpenAI({ apiKey }))
const result = await client.chat.completions.create({
  model: "gpt-4o-mini",
  messages,
  tools,
})
```

| Vertrag                               | Getestetes Verhalten                                                                                                                                               |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Geschützte semantische Werte          | Nachricht- und Systemtext, Tool-Argumente und Tool-Ergebnisse werden vor dem Client geschützt.                                                                     |
| Rehydrierte semantische Werte         | Antworttext, Stream-Deltas, an Tools gelieferte Argumente und Tool-Ergebnisse werden an ihrer Protokollgrenze rehydriert.                                          |
| Erhaltene Steuerung / opake Werte     | Rollen, IDs, Modell/Optionen, Tool-Namen, Metadaten und opake Provider-Felder bleiben erhalten; persönliche Felder bleiben Verantwortung des Aufrufers.            |
| Nicht unterstützte Varianten / Fehler | Nicht unterstützte Client-Formen schlagen ohne stillen Fallback fehl. Abort- und Provider-Fehler behalten den primären Fehler; für JSON/Tools `token()` verwenden. |

Der strukturelle Wrapper deckt auch Grok/xAI, Groq, Together, OpenRouter und
Ollama ab. Eine implizite Session wird mit dem Wrapper erzeugt und über dessen
Aufrufe wiederverwendet. Pro privater Konversation wird ein Wrapper verwendet;
alternativ macht `{ session }` den Besitz explizit. Für manuelle Loops gibt es
`createPiiChat`, `rehydrateToolArgs` und `createStreamingRehydrator`.

## Vercel AI SDK — `local-pii/ai-sdk`

```ts
import { openai } from "@ai-sdk/openai"
import { streamText } from "ai"
import { withPii } from "local-pii/ai-sdk"

const model = withPii(openai("gpt-5.2"), { session: conversation })
const result = streamText({ model, prompt })
```

| Vertrag                               | Getestetes Verhalten                                                                                                                                                                                   |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Geschützte semantische Werte          | System-/User-/Assistant-Text, Tool-Input/-Output und strukturiertes JSON werden geschützt. Reasoning ist opak und bleibt Verantwortung des Aufrufers.                                                  |
| Rehydrierte semantische Werte         | Text, Tool-Argumente vor Tool-Ausführung und Ergebnisse im nächsten Schritt werden rehydriert. Reasoning-Teile werden unverändert durchgereicht.                                                       |
| Erhaltene Steuerung / opake Werte     | Typen, IDs, Rollen, Reasoning, Tool-Namen, Freigaben, Optionen und Stream-Marker bleiben unverändert; Aufrufer-Metadaten werden nicht untersucht.                                                      |
| Nicht unterstützte Varianten / Fehler | Nicht unterstützte Inhalte und ungültige Streams schlagen fehl. Abort- und Provider-Fehler behalten den exakten Fehler; ein vor der Provider-Grenze beobachteter Abort verhindert den Provider-Aufruf. |

`withPii` ist Middleware und braucht keinen Tool-Wrapper. Eine übergebene Session
ist geliehen; ohne sie besitzt die Middleware eine Session für ihre Instanz und
verwendet sie über Aufrufe hinweg. Für eine neue private Konversation wird ein
neuer Wrapper erstellt. Der Browser-Playground pinnt `ai@7.0.57`,
`@ai-sdk/react@4.0.61` und `@browser-ai/core@3.0.0`.

## TanStack AI — `local-pii/tanstack`

```ts
import { createAnonymizer, token } from "local-pii"
import { piiConnection } from "local-pii/tanstack"

const session = createAnonymizer({ placeholders: token() }).createSession()
const connection = piiConnection(browserConnection, { session })
// useChat({ connection })
```

| Vertrag                               | Getestetes Verhalten                                                                                                                                    |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Geschützte semantische Werte          | Textnachrichten, unterstützte strukturierte Inhalte, Tool-Ein-/Ausgaben und Stream-Grenzen werden ohne Mutation geschützt.                              |
| Rehydrierte semantische Werte         | Text-Deltas, strukturierte Werte, Tool-Argumente und -Ergebnisse werden an der TanStack-Grenze rehydriert.                                              |
| Erhaltene Steuerung / opake Werte     | Rollen, Nachrichten-/Run-/Thread-IDs, Ereignistypen, Ende-/Fehlermarker und opakes `data` bleiben erhalten; Hydration wird durchgereicht.               |
| Nicht unterstützte Varianten / Fehler | `UnsupportedTanStackSemanticContentError` lehnt nicht unterstützte Teile ab; Abort-, Cleanup- und überlappende Run-Fehler behalten den primären Fehler. |

Der Vertrag ist auf `@tanstack/ai@0.43.1`, `@tanstack/ai-client@0.23.1` und
`@tanstack/ai-react@0.19.1` festgelegt. Der Aufrufer liefert eine Session pro
privater Konversation. Hydration und `joinRun` funktionieren nur mit derselben
lebenden Session. Persistence, vollständige Reload-Wiederherstellung,
Cross-Tab-Wiederherstellung und eine neue Session werden nicht unterstützt.
Seit 0.1.0 sollten nicht unterstützte semantische Teile in Text oder eine
unterstützte Struktur migriert werden.

## Platzhalterstrategie wählen

Für normalen Text eignet sich das lesbare `sequential()`, für stabile
Gleichheit das gekeyte `hashed({ secret })` und für Tools oder maschinell
verarbeitetes JSON das opake `token()`. Das private Mapping ist kein
Protokollfeld und muss innerhalb der Vertrauensgrenze des Aufrufers bleiben.
