# Browser generation primary-source check

Research date: 2026-08-11. Scope: [issue #22](https://github.com/CarlosZiegler/local-pii/issues/22), especially [Task 7](../superpowers/plans/2026-08-11-adapter-first-privacy.md). ### Exact q4f16 pipeline artifacts at the pinned model revision

The six paths were resolved with Transformers.js 4.2.0 `ModelRegistry.get_pipeline_files("text-generation", ..., { device: "webgpu", dtype: "q4f16" })`; byte sizes are repository blob sizes from the model's [immutable expanded tree](https://huggingface.co/api/models/onnx-community/gemma-3-270m-it-ONNX/tree/2dbbfdb1b59bd034eb959428c6a7da9dd7ea27f0?recursive=true&expand=true).

| Path                         |                                         Bytes |
| ---------------------------- | --------------------------------------------: |
| `config.json`                |                                         1,652 |
| `generation_config.json`     |                                           202 |
| `tokenizer_config.json`      |                                         2,313 |
| `tokenizer.json`             |                                    20,323,013 |
| `onnx/model_q4f16.onnx`      |                                       330,717 |
| `onnx/model_q4f16.onnx_data` |                                   272,626,176 |
| **Total**                    | **293,284,073 bytes (~293.3 MB / 279.7 MiB)** |

This total excludes the Transformers.js/ONNX Runtime application bundle, HTTP/browser cache overhead, and any future revision change. Requests begin at `https://huggingface.co`; Hugging Face documents that resolved downloads may use a CDN, and its current Hub storage is backed by Xet/S3. Following the pinned [large-file resolve URL](https://huggingface.co/onnx-community/gemma-3-270m-it-ONNX/resolve/2dbbfdb1b59bd034eb959428c6a7da9dd7ea27f0/onnx/model_q4f16.onnx_data) from Europe on 2026-08-11 redirected to `https://us.aws.cdn.hf.co`, not `https://cdn-lfs.hf.co`. That hostname is an observation, not a portable guarantee. [Hugging Face's downloader API](https://huggingface.co/docs/huggingface_hub/en/package_reference/file_download) explicitly treats the resolved location as either a Hub or CDN URL; [Hub storage documentation](https://huggingface.co/docs/hub/storage-backends) describes the Xet/S3 split.

An installed-Chrome 151 activation trace on 2026-08-12 additionally observed

| **Total**                              |     **23,614,439** |

The browser received Brotli-compressed transfers in that trace, so actual wire
bytes were lower. The runtime disclosure conservatively combines these support
artifact sizes with the six pinned model files: **316,898,512 static artifact
bytes (~316.9 MB) before transfer compression**. These support files are not
model files and therefore are not added to the model prefetch/cache manifest.

## Inferences and implementation implications

These conclusions apply the confirmed sources above to the proposed seam; they are not browser or library guarantees.

1. **The overall docs-private seam is viable without global mutation.** Discover `window.LanguageModel` read-only, check `availability()` with the intended creation options, and acquire only after the protected-request guard. Create one session with `initialPrompts`, pass the runtime signal to `promptStreaming(protectedContent, { signal })`, convert its stream iterator to the common async iterable, and call `session.destroy()` in `finally` on every terminal path.

2. **Do not rely on iterator `return(reason)` alone for Chrome abort semantics.** The common helper should still call `return()` for consumer cleanup, but only the Prompt API's `signal` path is specified to error the stream with the original abort reason; stream cancellation ignores that reason. `destroy()` is synchronous, though the surrounding runtime should await iterator settlement before reporting disposal complete.

3. **The model disclosures need two corrections.** Label the Chrome/browser-managed runtime “Gemini Nano” and the explicit fallback “Gemma 3 270M IT (ONNX)”. Replace the planned `446_693_376` estimate with approximately `293_284_073` for the pinned current six-file set, or compute metadata from `ModelRegistry` so a mutable `main` revision cannot silently stale the disclosure.

4. **A fixed `cdn-lfs.hf.co` origin is currently inaccurate.** Keep `https://huggingface.co` as the stable initiating origin. If disclosure/test policy must describe redirect destinations, model them as a Hugging Face CDN family (currently observed `https://us.aws.cdn.hf.co`) rather than treating any one CDN hostname as stable. Pinning the model revision makes bytes and file identities reproducible, but does not make a regional CDN hostname permanent.

5. **The planned turn contract loses accepted system content.** Chrome supports a real system role and Gemma's template supports a leading system message, while `ProtectedBrowserTurn.role` only permits `user | assistant` even though Task 7 says the Vercel adapter accepts system text. Either add `system` to the protected turn contract with an “optional first only” invariant, or explicitly reject system messages before runtime acquisition; silently dropping or coercing them would violate the shared-seam claim.

6. **The planned contract also admits histories Gemma rejects.** The seam has no alternation invariant, while this Gemma template throws on consecutive same-role messages or a history that begins with assistant. Canonicalize by merging adjacent same-role text before acquisition, or validate/reject the unsupported shape before the model/pipeline is acquired. Chrome's wider message grammar should not hide that fallback constraint.

7. **Keep one interrupt criterion per Gemma run and wait for cooperative settlement.** Its interrupted flag is sticky and the generation loop observes it between token steps. Per-run instances prevent one cancellation from leaking into a later request; runtime `dispose()` should interrupt active runs, await their generation promises/iterators, and only then release the cached pipeline.

8. **Use one chat-templating layer.** Passing a chat array to the text-generation pipeline lets the pipeline apply the template, or the runtime can call `apply_chat_template(..., { tokenize: false, add_generation_prompt: true })` and pass the rendered string. If rendering explicitly, ensure later tokenization uses `add_special_tokens: false`. The current template is the authority for role names and separators; hand-maintained prompt formatting will drift.
